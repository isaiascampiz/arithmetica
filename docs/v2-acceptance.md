# V2 implementation map

The upgrade is in the original `outputs/center-app` project. V1 students, codes, visits, observations, homework and regression cases are retained. The original file path stays `data/demo-v1.json`; its schema upgrades to 2 and an untouched V1 backup is saved before the migration.

| Requirement                        | Implemented location / workflow                                                                                                                                                                                                                                 |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Action-first iPad Home             | `StaffApp`: actionable status tiles, pinned global search, compact orientation/staffing row, internally scrolling live roster and assistance/correction/preparation queues                                                                                      |
| Expand/collapse sidebar; logo Home | Sidebar preference survives navigation; accessible Centerflow Home link; portrait, landscape, phone and desktop layouts                                                                                                                                         |
| Student/family management          | Roster create/search/filter; full-profile edit/withdraw/reactivate; family groups with shared recurrence and individual overrides; QR reissue invalidates old identifiers                                                                                       |
| Independent subjects/formats       | Profile settings: Math/Reading enrollment, Paper/CONNECT, level/ranges, next start, packet/day quantity, sheets/packet, classwork target, homework exclusions/caps                                                                                              |
| Automatic kiosk in/out             | One pouch scan toggles attendance; 30-second server debounce; camera rearm requires the same code to leave the frame; prior unverified visits require staff reconciliation                                                                                      |
| Staff attendance and duration      | Roster/profile quick in/out, instructor undo, assistant confirmation, live timers, center default and individual duration overrides                                                                                                                             |
| Unverified closing                 | Worker closes administratively using `closedAt`, leaves actual `departedAt` unset, preserves event history and exposes reconciliation                                                                                                                           |
| Schedules/exceptions/vacations     | Individual/family absences, vacations, make-ups and changed returns; center closures; expected today/next visit; automatic proposal recalculation; vacation last-visit workload and caps                                                                        |
| Corrections-first                  | Exact worksheet sets, remaining identities, complete/partial/deferred with reasons, age and visits persisted; block new classwork or preparation until addressed/deferred                                                                                       |
| Classwork and carryover            | Record/update exact classwork; separate verified completions; retained event/ledger history; unfinished identities replace proposed outgoing quantity; prevent double reservation and duplicate new pulls                                                       |
| Homework lifecycle                 | Decision needed/proposed/approved/ready/pulled/distributed/returned/partial/verified/corrections/repeated/deferred; author/timestamps; audited corrections revoke verification without deleting records                                                         |
| Preparation                        | Student/family/subject/attendance-date ordering, next operating day filter, exact ranges/packet/sheet amounts, paper-only pulling; CONNECT allocations remain separate; old packets stay in Legacy                                                              |
| Evaluations/notes/decisions        | Existing quick choices and optional text/dictation; optional subject; persistent pending review; categorical dimensions with Not assessed; explicit continue/repeat/advance/review with instructor approval                                                     |
| Profiles/charts                    | Overview, assignments, progress, evaluations, notes, attendance and QR; week/month/3-month/6-month/year/all-history; worksheet counts, verified durations, categorical timelines and homework return/completion records                                         |
| Achievement distinctions           | Manually verified, dated, subject-specific Bronze/Silver/Gold/Platinum with evidence; no automatic awards                                                                                                                                                       |
| Orientation calendar               | Day/week/month, create/edit/reschedule/cancel, instructor and duration, notes, coverage/additional graders, overlap and estimated instructional-demand warnings                                                                                                 |
| Reporting                          | Archived daily/weekly/monthly snapshots, manual revisions, CSV/JSON, missing/unverified records, physical versus official worksheet counts, upcoming students/preparation/orientations; manually entered actual completion dates support backlog reconciliation |
| Automatic jobs                     | Always-running Node worker or authenticated external scheduler; LA default 19:15 Mon–Thu, configurable; catch-up and job-specific idempotency; manual midday reports cannot suppress the closing snapshot                                                       |
| Shared persistence                 | Local atomic file replacement with cross-process directory lock; server-mediated Supabase/PostgreSQL CAS adapter, append-only state recovery history, cloud Auth membership checks and secure production gates                                                  |
| Recovery                           | Owner export, checksummed backup tool, isolated restore drill, forward SQL migrations and non-overwriting cloud initialization                                                                                                                                  |

External validation remains necessary for live Supabase schema/RLS/auth/recovery and actual iPad camera/microphone/home-screen operation. Corporate/privacy approval and the exact official report format are prerequisites for real student data. No corporate portal integration or automatic grading is implemented or claimed.
