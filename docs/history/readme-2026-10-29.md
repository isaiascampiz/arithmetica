## Start and stop

Use Node **24.20.0** and pnpm **11.25.0**, the tested versions. Install Node from its official website and pnpm with `npm install -g pnpm@11.25.0` if needed. Git and VS Code are already installed on the migration computer.

Open a terminal **inside this folder**:

```powershell
pnpm install --frozen-lockfile --store-dir .pnpm-store
```

If Windows reports a symlink permission error, use this equivalent dependency layout:

```powershell
pnpm install --frozen-lockfile --store-dir .pnpm-store --node-linker=hoisted
```

Keep the lockfile; do not upgrade dependencies during ordinary setup. On a fresh clone, copy `.env.example` to `.env.local` once. Do not overwrite an existing configured file. The migration working copy retains its `data/` directory. Defaults use fictional local data without cloud credentials.

```powershell
pnpm dev
```

Open [the local preview](http://127.0.0.1:3000). Stop it with **Ctrl+C** in that terminal. For the optimized version, stop development first, then run `pnpm build` followed by `pnpm start`. A second copy can use `pnpm start --port 3001` if port 3000 is occupied. Preview links work only while that server runs on this computer.

The login screen uses one staff sign-in form with fictional owner credentials in demo mode; additional test accounts remain server-authorized. See [operations](../operations.md) for test defaults, configuration, backups and existing deployment guidance. These examples are not private production passwords; never reuse them for real access.

Traffic is one attendance card with Daily, Weekly, Monthly and Yearly ranges. Daily/Weekly retain a matching-weekday comparison; longer ranges show actual check-ins. Student search updates the graph, totals and optional punch list together. Reports show Visits, Observations recorded/not recorded, and Verified completed worksheets, with one continuous panel and section buttons switching the list. Scheduled daily/weekly/monthly archives remain preserved. Only monthly Excel export is offered: student, grade, subject, last verified level/worksheet, verified worksheets and ten-sheet packet equivalents. Receipt assumptions and planned packets are excluded. See [reporting and verification](../operations.md#reports-and-verified-completions).

The workspace opens dark and retains Light/Dark/System control. Profile editors use compact settings-style dialogs. Roster and preparation share identical toolbar/filter components; Home shows actual preparation state. Reception shows QR-reader scanning and full-name entry on one page; readers use keyboard/HID mode with an Enter suffix after OS pairing. Camera access requires HTTPS or localhost. No physical scanner or iPad compatibility claim is made without testing that device. See the [current design brief and implementation notes](../../.plans/arithmetica-continuous-ui-spec.md).

## Records and requests

Preserved local records live in `data/demo-v1.json`, now schema 3. Its old filename is intentional: changing it could create a second empty database. Source fixtures in `src/lib/seed.ts` are separate from changing records. A fresh clone has no `data/` and initializes fictional seed data; it does not contain your accumulated local history. Keep an independent records backup.

Run `pnpm demo:restore` in a development checkout to reconstruct the 96 fictional students at schema 3. The command uses only checked-in fictional fixtures, preserves an existing complete demo roster without writing, and refuses production/cloud-database mode. The cloud setup script runs it automatically. It does not upload or reproduce local visit/observation history; that history stays in the preserved local backup.

A screen uses `src/lib/client.ts` to send JSON to `/api/commands`. The server checks login, role, input and version, applies a domain rule, then saves through `repository.ts`. Screens read the latest authorized snapshot from `/api/state`. Browsers never open the server's JSON file or receive its database service key. See the [architecture diagram](../architecture.md#beginner-map).

### Appearance and shared report headers

General places Accent color immediately below Theme. Twelve contrast-checked palettes recolor the existing accent tokens in charts and feedback; skill identities keep their original per-skill palette, and their overall average stays neutral. Only the non-record device preference `cf-accent` is stored beside `cf-theme`. No center record or authentication data enters browser storage.

Traffic and Reports reuse `WorkspacePeriodControls`: identical search geometry, native calendar input with Today in its own field, and Daily/Weekly/Monthly/Yearly navigation outside the card. Traffic fits noon through 7 PM without horizontal scrolling while retaining all-hour totals and accessible data. Reports uses short section labels and a two-column phone rail beneath a dated document heading. Yearly is a read-only `ReportView`; `Report` archive kinds, scheduled jobs, existing snapshots and monthly-only Excel rules remain unchanged. The server uses the existing authorization, revision and no-store protections.

Reception uses original full-screen contours and a restrained accent glow, without a central logo illustration. Pointer response moves only the decorative background. Arrival turns the background green; departure turns it red. A one-time expanding ring and contour response accompany the explicit named receipt without blocking controls. Reduced motion keeps static semantic colors and a brief opacity fade. The planar geometric brand and SVG/PNG/PWA assets are consistent, with aligned 44px sidebar controls in expanded/collapsed layouts. No dependency, schema migration or data rewrite is introduced.
